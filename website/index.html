Commands Reference

Every Command, Explained

All commands are Discord slash commands. Parameters in <angle brackets> are required; [brackets] are optional.

/deal start <counterparty>
Opens a private DM wizard (6 steps) to create a new deal: select network, your username, counterparty username, deal type (hosting, gifting, promotion, collab, other), amount + currency, and due date. Creates deal in PENDING_CONFIRMATION status and notifies the counterparty.
counterparty — Discord user you're dealing with (required). Cannot deal with yourself or a bot.
/deal confirm <deal_id>
Confirms a pending deal. Both parties must call this command before the deal moves to ACTIVE status.
deal_id — 8-character deal ID (e.g. 3F9A2B01)
/deal complete <deal_id>
Signals your side of the deal is done. Works from ACTIVE or OVERDUE status. Once both parties call this, the deal moves to COMPLETED and reputation scores update.
/deal dispute <deal_id> <reason>
Flags a deal as disputed. Freezes reputation score updates until an admin resolves it. Subject to server-configured dispute cooldown.
reason — Description of the dispute (10–500 characters, required)
/deal note <deal_id> <note>
Appends a permanent, immutable note to a deal. Notes cannot be edited or deleted. Only parties to the deal may add notes.
note — 3–1000 characters
/deal view <deal_id> [audit]
Shows full deal details: parties, status, amounts, confirmation flags, and notes. Set audit=true to include the complete immutable audit trail of every status change.
/deal list [status] [network]
Lists all your deals with pagination (8 per page). Filter by status (active, completed, disputed, etc.) or by network (TikTok, BigoLive, etc.).
/deal search <deal_id>
Finds and displays a specific deal by its 8-character ID. You must be a party to the deal to view it.
/rep <user> [network]
Displays a user's weighted reputation score and full deal history, broken down by platform network with a global aggregate. Anyone in the server can check any user's reputation.
user — The Discord member to look up (required)
network — Optional: filter score to one specific platform (autocomplete supported)
/admin resolve <deal_id> <resolution> [note]
Resolves a disputed deal by setting it to a new status. Admin or mediator role required.
resolution — active, completed, or defaulted
note — Optional admin note recorded in the audit log
/admin export
Exports all deals visible to the requesting admin as a CSV file attachment. Useful for agency recordkeeping and accounting.
/admin backup
Triggers an immediate SQLite database backup stored in the configured BACKUP_DIR. Backups run automatically daily at 02:00 UTC.
/admin stats [days]
Displays command usage statistics for this server over the last N days (default: 30).
/rate_limits view
Shows the current rate limit configuration for this server.
/rate_limits set [options]
Admin only. Configure server-specific limits — any omitted parameter keeps its current value.
max_open — Max open deals per user (default: 10)
max_volume — Max daily deal volume per user (default: 50,000)
cooldown_hours — Hours between disputes per user (default: 24)
reminder_mins — Reminder loop frequency in minutes (default: 30)
weekly_summary — Enable weekly digest DMs (default: true)
mediator_role — Role name with mediator permissions (default: DealMediator)
/export_data
Downloads all your personal deal data as a CSV file (GDPR-style export). Includes all deals you were party to and all notes you authored.
/about
Shows a public info embed explaining what DealBot does, what it doesn't do, its data policy, and how cross-network reputation scoring works.
Deal Lifecycle

From Handshake to Completion

Every deal follows a strict state machine. Status transitions are logged immutably — nothing can be silently changed after the fact.

🟡 PENDING → 🟢 ACTIVE → 🔵 PENDING COMPLETION → ✅ COMPLETED | also: ACTIVE → 🔴 DISPUTED → RESOLVED or ⛔ DEFAULTED
🟡 PENDING_CONFIRMATION

Deal created, awaiting confirmation from both parties. Counterparty is notified via DM.

🟢 ACTIVE

Both parties confirmed. Deal is in progress. Reputation scores are being tracked.

🔵 PENDING_COMPLETION

One party marked their side done. Waiting for the other to confirm completion.

✅ COMPLETED

Both parties confirmed. Deal closed successfully. Positive rep impact applied.

🔴 DISPUTED

Flagged by a party. Reputation updates frozen until admin/mediator resolves it.

🟠 OVERDUE

Deal is past its due date and not yet resolved. Both parties receive DM alerts.

⛔ DEFAULTED

Admin-set terminal status for failed deals. Negative rep impact recorded.

⚫ CANCELLED

Cancelled before the deal was ever activated. No rep impact.

How Scoring Works

Each deal contributes a signed weighted score based on:

  • Recency — Scores decay with a 180-day half-life. Recent deals matter more.
  • Volume — Larger deals are weighted more, using a log scale to prevent gaming.
  • Outcome — Completed = positive. Defaulted or overdue = negative. Disputed = excluded (frozen).
  • Per-network — Scores are calculated per platform, plus a global aggregate.

Use /rep @user to check anyone's score. Filter by network to see platform-specific trust levels.

Privacy & Data

Your Data, Transparent and Portable

DealBot stores only what's needed to operate the ledger. No third-party services. No hidden data sharing.

🗄️

Local SQLite Storage

All data is stored in a local SQLite database on the bot's host server. No external databases or cloud services.

📤

Personal Data Export

Use /export_data at any time to download all your deals and notes as a CSV. GDPR-style portability built in.

🔒

Encrypted Backups

Daily automated backups at 02:00 UTC. Optional AES-256-GCM encryption for sensitive deployments.

📜

Immutable Audit Log

Every status change is append-only and tamper-evident. The audit trail cannot be altered retroactively.

🚫

No Third-Party Sharing

No data is sent to any third-party service. What goes into DealBot stays in DealBot.

🔔

DM Reminders

Automatic reminders at ≤48h, ≤24h before due dates, and on overdue. Weekly digest on Sundays 00:00 UTC (configurable).

⚠ Disclaimer: DealBot records voluntary agreements only. It does not handle, hold, or move money or digital assets. It does not enforce deals legally or financially. It does not determine fraud — only records objective outcomes. DealBot is not affiliated with BigoLive, TikTok, Tango, YouTube, or Twitch. Use responsibly and in good faith.
